# Three-way cloud conflict planning
2026-11-27 — follow-up to 8847cd0.
Atomic manager now saves a normalized full conversation/message/state baseline in local IndexedDB on confirmed push (same index transaction) and after confirmed pull. If the observed cloud revision differs from that baseline, it performs a read-only stable revision check, fetches conversation metadata, messages and state, verifies unchanged media indexes, and plans a three-way merge. The proposed local/remote/merged snapshots and revisions are saved locally; no remote mutation or local runtime replacement is performed by the planner.
Merge uses exact message IDs and ordered per-conversation history. Independent conversations and nonoverlapping object fields are merged. Concurrent complete append-only tails may be preserved remote-first as complete blocks; conflicting edits/deletions, incomplete or overlapping turns and conflicting state fields stop. Arrays and serialized setting strings are atomic values, not guessed merges. This preserves data, not necessarily narrative semantics.
