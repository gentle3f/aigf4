# G8J isolated story state + recall checkpoint laboratory
Base c81baf9. Experimental SQL only, depends on V2 checkpoint; not applied to cloud.
Run: npm exec -- tsx tests/storyCheckpointLab.pg.mjs
Uses actual schema and RLS in isolated PGlite with synthetic owner claims and story data. Each transaction checks global state revision and conversation history digest/count, then appends text or recalls only the latest user turn and its trailing messages, and saves a site-scoped JSON snapshot with the resulting history digest. Other-site snapshots for the same conversation are explicitly invalidated even if later recall returns to the same history hash. Unrelated wetapp_state.payload is preserved. Snapshot write failure rolls back chat and revision. No model API calls or live cloud writes.
10/10 SQL tests: append and metadata atomic, stale revision, other-site invalidation, reject non-tail recall, pending old fingerprint rejected after recall, owner auth, history hash ABA, media recall rejected, completed user/model recall, injected failure rolls back.
Limitations: caller-supplied world/director/prompt snapshot; not yet wired to actual Worldline serialization or restoration. Existing shared history is not partitioned by site; only snapshot records are separate. No new conversations, settings-only save, media handling, arbitrary earlier turn removal, or automatic conflict resolution. Current legacy clients bypass the new transaction and must be fenced before live deployment. Do not execute on production; next build authenticated lab transport and real app state capture/restore against this protocol before any rollout.
